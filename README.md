# 주소등록이

## 1. 제목
주소등록이

## 2. 핵심 기능
- 택배 받는 사람 이름 입력
- 도로명 주소 검색 및 등록
- 전화번호 입력
- 집 주소 등록 및 관리
- 메모 작성 기능
- 기본 배송지 설정
- 주소 수정 및 삭제
- 주소 중복 및 형식 검증
- 관리자용 주소 관리 기능

## 3. UI
- 메인 화면: 노트장 형식으로 구성, 상단에 날짜 입력 가능
- 메인 화면 레이아웃: 상단 날짜 > 하단으로 내려가며 좌측부터 이름, 전화번호, 주소(도로명/집), 우측에 메모장 배치
- 주소 목록 화면: 등록된 주소 리스트 및 기본 설정
- 상세 입력 화면: 도로명/지번/상세주소 입력
- 관리자 화면: 사용자 주소 관리 및 이력 확인

### 메인 화면 구성 예시
- 상단: 날짜 입력 영역
- 좌측 영역: 이름, 전화번호, 주소 입력
- 우측 영역: 메모장
- 하단: 저장, 수정, 삭제 버튼

예시 형태:
- [날짜: 2026-10-17]
- [이름] [전화번호]
- [도로명 주소]
- [집 주소]
- [메모장]

## 4. 기대 효과
- 주소 입력 시간 단축
- 주소 입력 오류 감소
- 데이터 품질 향상
- 사용자 편의성 증가
- 운영 효율성 개선
- 재사용 가능한 주소 데이터 확보

## 5. 페르소나
### 페르소나 1: 일반 사용자
- 이름: 김민지
- 연령: 29세
- 직업: 사무직 사원
- 문제: 회원가입, 배송지 등록 시 주소를 정확하게 입력하는 것이 번거롭다.
- 목표: 빠르고 정확하게 주소를 등록하고 싶다.

### 페르소나 2: 자영업자
- 이름: 박준호
- 연령: 41세
- 직업: 소규모 사업자
- 문제: 고객 주소를 반복적으로 입력하고 관리하는 일이 불편하다.
- 목표: 고객 주소를 빠르게 저장하고 관리하고 싶다.

### 페르소나 3: 관리자
- 이름: 이서연
- 연령: 35세
- 직업: 운영 관리자
- 문제: 주소 데이터가 중복되거나 수정 이력이 관리되지 않는다.
- 목표: 주소를 체계적으로 관리하고 오류를 줄이고 싶다.

## 6. 문제 정의
- 주소를 직접 입력할 때 오타와 누락이 자주 발생한다.
- 주소 검색이 불편하고, 검색 결과를 이해하기 어렵다.
- 주소 정보가 여러 곳에 중복 저장되어 관리가 어렵다.
- 기본 주소 설정 및 변경 이력이 부족해 운영 불편이 발생한다.
- 사용자와 관리자 모두 주소 관리에 많은 시간을 소모한다.

## 7. 핵심 화면
1. 메인 노트장 화면
   - 상단에 날짜를 직접 입력 가능
   - 아래로 스크롤하며 이름, 전화번호, 주소를 순서대로 입력
   - 좌측에는 이름/전화번호/주소, 우측에는 메모장 배치
   - 사용자가 한눈에 기록할 수 있도록 구성
2. 주소 등록 화면
   - 도로명 주소, 집 주소, 상세 주소 입력
   - 기본 주소 설정 기능 포함
3. 주소 목록 화면
   - 등록된 주소 목록 표시
   - 기본 주소와 최근 사용 주소 구분
4. 수정/삭제 화면
   - 기존 주소 수정, 삭제, 메모 수정 기능
5. 관리자 화면
   - 사용자별 주소 관리, 수정 이력 확인

### 화면 레이아웃 예시
- 상단: 날짜
- 좌측 열: 이름 / 전화번호 / 주소
- 우측 열: 메모장
- 하단: 저장 버튼

예시:
- 이름: 홍길동
- 전화번호: 010-1234-5678
- 도로명 주소: 서울시 강남구 테헤란로 123
- 집 주소: 서울시 강남구 역삼동 456-7
- 메모장: 택배 반품 요청, 문 앞 보관

## 9. TRD (기술 기획 문서)
### 9-1. 기술 목표
- 주소 검색 및 입력 UX 개선
- 주소 데이터 정확성 확보
- 관리자용 주소 관리 기능 구현
- 확장 가능한 구조 설계
- 보안 및 개인정보 보호 강화

### 9-2. 기술 구성
- Frontend: React / Next.js 기반 UI
- Backend: Node.js, Express 또는 NestJS
- Database: PostgreSQL 또는 MySQL
- API: 주소 검색 API, 주소 CRUD API
- Auth: 로그인 기반 사용자 인증
- Infra: AWS 또는 Azure 기반 배포

### 9-3. 주요 기능 구현 방식
- 검색 기능: 외부 주소 API 연동
- 검증 기능: 기본 필수값, 우편번호 형식 체크, 중복 방지
- 데이터 저장: 사용자별 주소 테이블 구성
- 기본 주소: is_default 플래그 기반 관리
- 이력 관리: 수정/삭제 로그 저장

### 9-4. 데이터 구조 예시
- users
  - user_id
  - name
  - email
  - phone
- addresses
  - address_id
  - user_id
  - postcode
  - road_address
  - jibun_address
  - detail_address
  - is_default
  - created_at
  - updated_at
- address_history
  - history_id
  - address_id
  - action
  - old_value
  - new_value
  - changed_at

### 9-5. 비기능 요구사항
- 응답 속도: 주소 검색 1초 이내
- 보안: HTTPS, 사용자 권한 분리
- 안정성: 예외 처리 및 로그 관리
- 확장성: 향후 관리자 기능 및 외부 API 연동 가능

### 9-6. 개발 난이도
- 중급 수준
- 핵심은 주소 검색 API 연동 + 검증 로직 + 사용자별 데이터 관리 구조 설계

## 10. 최종 정리
주소등록이는 단순한 주소 입력 기능이 아니라, 사용자가 빠르고 정확하게 주소를 관리할 수 있도록 돕는 서비스다. 사용자 편의성과 운영 효율을 동시에 높일 수 있으며, 한 달 내 MVP 개발이 가능한 범위로 구성하는 것이 적합하다.

### 결론
- PRD: 사용자 문제, 기능, 페르소나, 기대효과 중심
- TRD: 기술 구성, 데이터 구조, API 설계, 개발 일정 중심
- 목표: 빠르게 출시 가능한 MVP를 만들고, 이후 기능 확장을 통해 서비스 고도화
